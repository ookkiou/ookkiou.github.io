评测的本质假设是：测试题模型没见过，分数反映的是泛化能力。但现实是两层都在漏：第一层，底座模型的预训练语料爬了半个互联网，而 CMB、GSM8K 这些 benchmark 的题目和解析早就公开在网上了——底座很可能已经"背过答案"；第二层，你自己构建训练数据时，从公开数据集取材、用强模型蒸馏生成，都可能把 benchmark 原题或变体带进训练集。一旦训练数据里有测试题，评测分数就是虚高的，整个项目的对比结论全部失效——这不是小瑕疵，是会被面试官一票否决的硬伤。

注意这里有个诚实边界：第一层（底座自带污染）你管不了，Gemma 吃了什么你无法追溯；**你能 claim 的只是"我保证了我自己引入的增量数据无污染"**。面试时这两者要说清楚，否则反而露怯。

**污染长什么样**，比"原题照搬"狡猾得多：精确污染（题目原样出现）只是最简单的一种；更常见的是模糊污染——换了个问法的改写题、中英文互译、数学题换了数字但结构一致、甚至解析文本里引用了题目知识点。所以去污染也分级，从便宜到贵：

主流做法是 **n-gram 重叠检查**：把训练数据和评测题都切成连续的 n 个字符片段，查评测题的片段是否大量出现在训练数据里。n=13 是 GPT-3 时代传下来的惯例——n 越大越精确但漏掉改写，n 越小越敏感但误报多。工程上一般不要求"命中一个 gram 就算"（常见短语会造成大量误报），而是看命中率超过阈值（比如 80%）才判污染。

```
import re, json

def normalize(text: str) -> str:
    # 去空白、去标点、小写化——污染常伴随格式差异，先归一再比
    return re.sub(r'[\s\W_]+', '', text.lower())

def ngrams(text: str, n: int = 13):
    return {text[i:i+n] for i in range(len(text) - n + 1)}

def build_index(train_files, n=13):
    """把所有训练数据（SFT、偏好对的 prompt、GRPO 的 prompt、CPT 语料）
    的 n-gram 汇成一个集合"""
    idx = set()
    for f in train_files:
        for line in open(f):
            sample = json.loads(line)
            idx |= ngrams(normalize(sample["text"]), n)
    return idx

def decontaminate(eval_questions, idx, n=13, thresh=0.8):
    hits = []
    for q in eval_questions:
        grams = ngrams(normalize(q), n)
        ratio = sum(g in idx for g in grams) / max(len(grams), 1)
        if ratio > thresh:
            hits.append((q, round(ratio, 3)))
    return hits   # 返回疑似污染题，人工复核后从训练集剔除
```

几个设计点值得理解：normalize 在前是因为污染往往带着格式差异（空格、标点、大小写）进来；中文没有空格，字符级 13-gram 天然可用；判出疑似命中后**人工复核再删**，不要无脑自动删，阈值误伤的样本会悄悄改变你的数据分布。

比 n-gram 更进一步的是 **embedding 相似度检查**：把评测题和训练样本都编码成向量，查余弦相似度过高的对——这能抓到 n-gram 抓不到的改写题，成本是跑一遍编码器。预算允许的话，n-gram 先筛、embedding 复核，两级配合。再往上还有成员推断（测模型对该样本的困惑度是否异常低）和"活体 benchmark"思路（LiveBench 那种，只用模型训练截止日期之后发布的题目，从根上躲开污染），了解即可。

**落到你的三个项目**，检查对象要列全：医疗的 CMB/CMExam 题库 vs 你的 SFT 数据 + 2000 条安全偏好对的 prompt；数学的 GSM8K/MATH vs SFT 数据 + GRPO 的 prompt 集。另外记住前面流水线讲的两个原则：拆分在前（评测集先锁死当钥匙）、去污染在最末端当最后一道闸——尤其蒸馏生成的数据，强模型背过 benchmark，生成物是带着污染进来的。

最后闭环到前面讲的 lineage：去污染脚本本身有 git commit，跑完把"剔除了多少条、命中了哪些题"写进该数据版本的 lineage.json。这样面试被问"去污染怎么落地的"，你能答出：n-gram 脚本 + 阈值策略 + 人工复核 + 结果入 lineage——你 claim 清单里那条"仅有红线无脚本"的未落实项，这就是补齐它的具体路径。
