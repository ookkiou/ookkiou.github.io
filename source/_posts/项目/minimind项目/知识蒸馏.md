## 白盒蒸馏
### minimind 的白盒蒸馏
回顾 SFT：学生只看"标准答案 token"，算交叉熵（CE），这是 硬标签 。
白盒蒸馏多一步：让教师模型对同一个输入也做一次前向，得到它对 整个词表每个 token 的概率分布 （软标签）。学生不仅要预测对答案，还要让自己的分布形状贴近老师的分布。
```
SFT:     loss = CE(student_logits, labels)
蒸馏:    loss = α·CE(student_logits, labels) + (1-α)·KL(student || teacher)
```
为什么要学分布？因为软标签携带了"老师对候选词的相对偏好"——比如标准答案是"开心"，但老师给"高兴/快乐/愉悦"也都分配了不低的概率，这些暗知识（dark knowledge）比一个孤立的正确答案信息量大得多。


我们看看 Distillation Loss 的代码:
```
teacher_probs = F.softmax(teacher_logits / temperature, dim=-1).detach()
student_log_probs = F.log_softmax(student_logits / temperature, dim=-1)
kl = F.kl_div(student_log_probs, teacher_probs, reduction='batchmean')
return (temperature ** 2) * kl
```
温度 T:T 越大分布越平缓，暴露出更多次优 token 的相对关系。T 等于一就是原始分布。
为什么要 T 方缩放？因为 Softmax 被 T 软化后，梯度呢会缩小约 T 的平方倍，我们乘回来保持梯度量级一致。这是 Hinton 原论文的标准 trick。
detach() 教师 ：教师不参与反向传播，只提供目标分布，全程不更新。另外教师的词表要截断到学生的词表，这样是防止教师词表比学生大的情况。


训练循环其余部分（lr 调度、梯度累积、断点续训、保存）和 train_full_sft.py 一模一样。
这里模拟用 MoE 模型蒸馏 Dense 模型，设计意图是 MoE 模型参数量大，表达能力强，可以当老师。Dense 模型小，可以当学生。
### 温度 T
在知识蒸馏中，模型最终输出的概率（比如“猫”的概率）不是直接用的原始分数（logits），而是经过一个带温度参数 T 的 **Softmax 函数** 重新计算：
![590](Snapzy_2026-08-10_21-42-06_673.png)
根据 T 的大小，会发生截然不同的情况：
- **当 T = 1 时**：这就是标准的 Softmax 函数。模型会给出一个非常“自信”的判断，比如 [0.9, 0.06, 0.04]。这相当于直接告诉学生：“它就是猫，别想了。” 学生只能学到正确答案，学不到其他类别的相对关系。
- **当 T > 1 时（核心用法）**：T 越大，概率分布就越“平滑”或“柔软”。还是那张猫的图片，当 T 值调高后，概率分布可能变成 [0.5, 0.3, 0.2]。这相当于告诉学生：“它极大概率是猫，但和狗、兔子也有点像，尤其是比兔子的相似度高一点点。” 这多出来的信息，就是教师模型对世界的理解，也叫 **“暗知识”**。
- **当 T 非常大时**：所有类别的概率会趋向于相等，分布过于平滑，有用的“暗知识”会被稀释，变成无意义的噪声。
- 太小的 T（如1.0）意味着“填鸭式教学”，只给结论，不给思路，学生容易死记硬背，泛化能力差。太大的 T（如20.0）意味着“抽象式教学”，讲得太泛，学生抓不住重点，也学不好。
在实际训练中，工程师们通常会采用一个非常经典的策略：
- **用大 T（比如 4 或 20）** 来软化教师模型的输出，让学生模型去模仿这个“软标签”。这一步是为了让学生学会教师的推理逻辑。
- **同时，也用小 T（T=1）** 让学生模型去学习训练数据的真实标签（硬标签）。这一步是为了保证学生的答案最终是正确的。
- 最终的损失函数通常是这两部分损失的加权组合。这就像学生既要学习老师的解题思路，也要确保最后算出的答案是对的。
## 黑盒蒸馏
把老师当成一个 只能调用的 API ：输入 prompt → 拿到老师的输出文本 → 把这个文本当成"标准答案"让学生做 SFT。
学生只看到老师 最终说了什么 ，看不到老师对每个候选词的概率分布、也看不到中间层激活。
相当于用其他模型的输出，来作为训练模型的输入。
