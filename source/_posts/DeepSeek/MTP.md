## 为什么要 MTP
标准的大模型使用的是 NTP，也就是 next token prediction。模型呢，只看前边的 token，预测紧邻的下一个。这就带来了几个问题：
1. 短视监督 ：模型只关心"下一步"，缺乏对未来多步的规划压力，容易学到局部统计规律而非深层语义。人类大脑在思考的时候，不可能只想下一个字该怎么说，肯定是一起想出来的。
2. 训练效率低 ：每个 token 只贡献一次预测损失，数据利用率不高。
3. 训练-推理差距 ：训练时 teacher forcing 一步一预测，推理时却要自回归生成很长序列，错误会累积。
4. 表示浪费 ：深层 transformer 的中间层表示其实蕴含了远超一个 token 的信息，但 NTP 只用它预测一个 token。

## MTP 的局限
我们知道现在的推理框架，比如说 VLLM，支持动态 batch，可以让多用户同时访问大模型。它会把用户的多个请求组合成一个 Batch。这时 MTP 的预测加速就没有优势了。反而会因为可能验证不通过而浪费计算。所以 Deepseek MTP 只是在训练时利用 MTP 来提升模型性能。在推理部署时一般就丢弃掉其他几个预测头，就只用第一个头来预下一个 Token ，和普通的单头大模型没有区别。
## DeepSeek 的 MTP
原来的 MTP 预测呢，它有一些局限，比如说它要跨多个 Token 进行预测，后边预测的 Token 它不知道前边的token是什么，从而让预测正确率变低。比如它对于第 4 个 Token 的预测，它要在它不知道前面 3 个 Token 的情况下预测出来，这样难度非常大，不利于模型的收敛。

---

DeepSeek 的 MTP 做了一些改进，就是给每个预测头传入了额外的信息，帮助多 Token 预测能够更好地预测出自己的 Token。
输入头的来源有两个，一个是来自 Deepseek 第 L 层的 Token 特征。另一个是 T2 这个 Token 经过 embedding 后的特征。于这个 MTP 的输入头，它有关于 T2 的embedding，也有关于可以预测 T 二的特征，可以更好地预测出 T3。

## Deepseek 的 MTP 投机解码
Deepseek V3 在推理阶段可以使用 MTP 的投机解码技术来加速生成，但是需要手动进行专门配置。
那么在上一部分我们看到了 Deepseek 的 MTP 它是串行走的。普通生成 N 个前向查询，自回归也是串行走的，好像没什么区别。其实关键不是看次数，而是看每次代价。MTP head 是小模块，主模型是大模块。我们走 N 次小模块，肯定是比走 N 次大模块更省时间。
- 主模型 ：61 层 Transformer block（MLA + DeepSeekMoE），每层都很重
- MTP module ： 只有 1 个 Transformer block + 1 个投影矩阵
所以串行走 K 个 MTP head 时，每一步只走 1 层 ，而普通自回归每步要走 61 层 。

---
1. **草稿阶段（用小模型）**：找一个轻量级的“草稿模型”（在DeepSeek-V3里就是用MTP模块充当这个角色），让它快速连续生成几个甚至十几个token。这个模型速度极快，但质量可能一般。
2. **验证阶段（用大模型）**：把草稿模型生成的这一串候选token，一次性交给DeepSeek-V3这个大模型来“批改”。大模型很厉害，它可以**并行地**（就跟训练阶段一样，可以并行）一次性判断出其中哪些token写得好、哪些写得不好。
3. **接受与修正**：
    - 大模型会**接受**所有它认为正确的草稿token。
    - 一旦遇到第一个它认为不对的token，大模型会**直接给出正确的token**，并从那里继续往下生成。
